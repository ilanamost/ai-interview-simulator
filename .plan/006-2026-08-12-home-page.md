# Home Page

## Goal
Give the AI Interview Simulator a proper landing page. Today `/` is the interview-setup
form, so a first-time visitor lands directly in "configure a practice interview" with no
explanation of what the product is or why they'd use it. Add a `HomeView` that explains the
product in three sections and makes it the app's default route, and move the setup form to
its own route.

## Scope
- In scope (`web/`, frontend-only):
  - New `web/src/views/HomeView.vue` with three sections — what the app does, how it works,
    key features (with icons) — that together answer: what is this application, who is it
    for, what problem does it solve, how does it work, what should I do next.
  - Router change: `/` now renders `HomeView`; the existing setup form (currently at `/`)
    moves to `/practice`. `/interview` and `/report` are unchanged.
  - A primary call-to-action on the home page linking to `/practice` (answers "what should
    I do next"). One CTA in the hero, only — no duplicate closing CTA section.
  - New styles under `web/src/styles/cmps/` for the home page's sections, imported from
    `web/src/styles/cmps/index.css`, following existing token/spacing conventions in
    `web/src/styles/setup/variables.css`.
- Out of scope (explicitly, per `.doc/product-definition.md` — auth is not in scope for any
  current stage):
  - Login/signup and gating the home page behind authentication. The backlog's separate
    "Add authentication" task owns that; this plan does not touch it or block on it.
  - Any change to `api/`. This task carries no `stack:full` marker.
  - Changing what `/practice`, `/interview`, or `/report` render — only their entry path
    changes for the setup form.

## Assumptions
- "Start page of the application after logging in" in the backlog task describes the
  target end state once auth ships later; since there is no login yet, `/` simply becomes
  the home page for every visitor now. Revisit the router guard when the auth task lands.
- "Add another route for the interview practice (which is currently the only page)" means
  relocating the existing `SetupView` (currently mounted at `/`) to a new path, not writing
  a new practice screen — `SetupView` already *is* the interview-practice entry point.
- The header brand link (`web/src/App.vue`, `RouterLink to="/"`, text "AI Interview
  Simulator") already points at `/`; once `/` is `HomeView` this satisfies "the header link
  goes to the home page" with no change to `App.vue`.
- "Key features list (with icons)" uses `lucide-vue-next`, the icon library already used
  throughout `web/` (`.claude/rules/ui-and-styling.md`).

## Open Questions
1. What path should the relocated setup form use — `/practice` or `/setup`?
   Recommendation: `/practice`, since the backlog task itself calls it "interview
   practice" and the header/nav copy elsewhere says "Practice your next interview."
2. Should the existing router guards that redirect to `{ name: 'setup' }` when there's no
   session (`/interview`, `/report`) keep redirecting to the practice form, or to the new
   home page? Recommendation: keep redirecting to the practice form (route name `setup`
   stays the same, only its `path` changes to `/practice`) — a user mid-flow who loses their
   session should land back on the form to restart, not back on marketing copy.
3. Does the unmatched-route catch-all (`/:pathMatch(.*)*`) still redirect to `/`?
   Recommendation: yes, unchanged — it will now land on the home page instead of the setup
   form, which is the more sensible default for an unknown URL.

## Steps
1. Add `web/src/views/HomeView.vue`:
   - Hero/intro section: what the app is, who it's for, what problem it solves.
   - "How it works" section: short numbered/step summary of the
     setup → question → evaluation → report flow.
   - "Key features" section: a list of feature items, each with a `lucide-vue-next` icon
     (e.g. role-specific questions, immediate feedback, quantified grading, resumable
     sessions), reusing existing `.card`/`.badge` style primitives where they fit.
   - A primary CTA button/link ("Start practicing" or similar) as a `RouterLink to="/practice"`.
2. Update `web/src/router/index.ts`:
   - Add `{ path: '/', name: 'home', component: HomeView }`.
   - Change the existing setup route's `path` from `/` to `/practice` (keep
     `name: 'setup'` so the two `router.beforeEach` redirects to `{ name: 'setup' }` need no
     change).
3. Add `web/src/styles/cmps/home.css` for section layout/spacing, imported from
   `web/src/styles/cmps/index.css`, using tokens from
   `web/src/styles/setup/variables.css` — no new Tailwind/CSS-in-JS dependency.
4. Record `.orchestrate/api-contract.yaml` as unchanged (this task adds no endpoint) —
   frontend agent still writes the file per its workflow, noting no new contract.

## Validation
- New `web/src/views/HomeView.spec.ts`: renders all three sections; the CTA is a link to
  `/practice`; each key-feature item renders with an icon.
- Update `web/src/router/index.spec.ts` (or add one, matching the existing router test
  pattern) to assert: `/` resolves to `HomeView`, `/practice` resolves to the setup form,
  and a session-less visit to `/interview` or `/report` still redirects to `/practice`.
- Manual check (`npm run dev`): visiting `/` shows the home page; the header brand link from
  any page returns to `/`; the CTA reaches the practice form; starting and finishing an
  interview still works end-to-end unaffected by the route change.
- `cd web && npm test`, `npx vue-tsc --noEmit`, `npm run lint` all pass.

## Risks
- Any hardcoded internal link or test that assumes the setup form lives at `/` will break —
  mitigated by Step 2's route-name-preserving approach (redirects target the `setup` name,
  not a literal `/` path) and by updating/adding the router spec in Validation.
- Scope creep into auth/gating, since the backlog task's own wording mentions "after logging
  in" — explicitly excluded above; flag it back to QA/product if the acceptance review
  expects gating now.

## Rollout Order
1. Router change + `HomeView` + styles (Steps 1–3), with tests.
2. `.orchestrate/api-contract.yaml` note (Step 4).
3. QA validates against this plan's Validation section and the relevant
   `.doc/product-definition.md` criteria (Success Metrics → Usability).

## Rollback
Single frontend-only commit set on `feat/home-page`, no data or API changes — revert the
branch/PR. No migration, no persisted-state shape change (the `localStorage` session
snapshot format in `session-storage.service.ts` is untouched), so rollback is a plain code
revert with no cleanup step.
